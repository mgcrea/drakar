# Rewind Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each of your prompts in a Drakar session offers "Fork conversation from here",
"Rewind code to here" and "Fork conversation and rewind code". A code rewind shows a dry
run before anything is written.

**Architecture:** Every Claude Code process Drakar starts gets file checkpointing switched
on. The kit keeps each prompt's CLI message uuid, encodes `rewind_files` and decodes its
reply, can cut a history before a prompt, and passes `--resume-session-at`. The app tracks
per process whether a rewind can work. It runs the dry run and the rewind through a small
`@Observable Rewinds` per session, and forks through `Project.fork(_:from:)`. The prompt
bubble's menu and a confirm sheet are the UI.

**Tech Stack:** Swift 6 (MainActor default isolation), SwiftUI/AppKit, swift-testing, the
DrakarKit SPM package. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-28-rewind-design.md`

## Global Constraints

- Work in a worktree under `.claude/worktrees/rewind` (never `../`). Merge `main` in and run
  `make -C apps/apple test test-app` before landing; land with `git merge --ff-only` in the
  main checkout. Main may hold another session's uncommitted edits. Touch none of them; if
  this branch must change one of those files, stop and ask.
- Never `make run` or `make quit`.
- Environment: `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING=true` for every Claude Code process
  Drakar starts, unless the environment it starts from has
  `CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING` set, which then wins. Codex is untouched.
- The extension's words, verbatim:
  - Menu items: "Fork conversation from here", "Rewind code to here", "Fork conversation and rewind code".
  - Sheet titles: "Rewind code", "Fork and rewind".
  - Fork note: "A new forked conversation will be created after rewinding."
  - Warning: "Restored files go back whole, losing later changes by anyone. Bash changes to other files are not undone."
  - Buttons: "Rewind", "Continue", "Never mind".
  - Outcomes: "Code rewind successful", "Failed to rewind code", "Failed to rewind: no checkpoint for this message".
- Drakar's own copy only where the extension has none: "No files to rewind." (an empty dry
  run in Fork and rewind). Strings through `String(localized:)`, no em dashes.
- No file is written without the person seeing the dry run's list and pressing Rewind. Code
  rewinds are offered only while Drakar drives the process, the process
  has not said "File rewinding is not enabled.", and no turn is running. Every menu item is
  disabled during a turn; nothing is queued.
- Rewind requests are written without a `SessionNote`, under `rewind-<UUID>` request ids, as
  the task controls are (`TaskControls.send`).
- Deployment target macOS 26.0. Format with `make -C apps/apple format-swift` before each
  commit.

## Review Focus

1. **The process ends between the dry run and Rewind.** Rewind should not send to a dead
   process: the sheet shows "Failed to rewind code" and closes nothing silently. Pinned by
   `RewindsTests.aRewindWithNoProcessFails` (Task 5).
2. **A dry run whose reply never comes.** The sheet must not spin forever: after 10 s it
   shows "Failed to rewind code". Pinned by `RewindsTests.noReplyFails` (Task 5).
3. **Paths outside the session's folder** (the agent edited `~/.zshrc`). They are listed
   whole, never cut to look like a project file. Pinned by
   `RewindsTests.pathsOutsideTheFolderStayWhole` (Task 5).
4. **Forking from a prompt that the history drops** (a compacted conversation, a prompt
   before a `/clear`). The menu offers no fork for a prompt with no message uuid. Pinned by
   `RewindOfferTests.noUUIDNoFork` (Task 6).
5. **The same prompt text twice in a session.** The fork cuts at the chosen one, by uuid,
   never by text. Pinned by `TranscriptHistoryCutTests.cutsAtTheUUIDNotTheText` (Task 2).
