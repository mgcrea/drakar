# Drakar: launch time and memory against VS Code

- **Measured:** 2026-11-01, on the owner's Mac (Mac17,6, M5 Max, 18 cores, 64 GB), under load from other sessions (load average 12 to 61 during the runs, which slows both apps alike).
- **Versions:** Drakar 1.1.0 as installed in `/Applications` (the Release build). VS Code 1.144.0 with Claude Code extension 2.1.314, in a separate profile holding only that extension (plus VS Code's built-in `copilot-runtime`, counted as part of VS Code). Both opened on the drakar repo, or for Drakar on its restored window.
- **Why:** the 2026-10-09 brief (§7.6) recommended leading with measured weight, not the word "native". This is the measurement. Website copy should cite it and nothing it does not cover.

## Results

| | Drakar | VS Code + Claude Code |
| --- | --- | --- |
| Launch to first window, median of 5 after a warm-up | **503 ms** (499–572) | **504 ms** (447–559) |
| Memory, project open with a conversation showing, the agent's own `claude` left out | **148 MiB**, 1 process | **875 MiB** after about a minute, 11 processes (1,497 MiB at 25 s) |

- **Launch time is a tie.** Do not claim Drakar opens faster than VS Code. VS Code's first window is only its shell, and its Claude tab comes later, but neither app's "ready to type" time was measured.
- **Memory is the gap:** about a sixth of VS Code's, a cautious figure. VS Code had a clean profile with one extension, so a real setup weighs more. Drakar was showing a short real conversation (about ten messages), VS Code an empty one. Drakar's session host (`DrakarHost`) was not running: it starts on demand, so a running session adds it.
- **Not measured:** memory or smoothness with a long transcript (the "thousand turns" of PLAN.md §1), and time until the composer accepts input. Run those before any copy claims them.

## Method, and the traps in it

Launch time: launch the app, then poll `CGWindowListCopyWindowInfo([.optionOnScreenOnly], kCGNullWindowID)` every 5 ms for a window owned by the app's pid at layer 0 and taller than 200 pt. This needs no Screen Recording or Accessibility permission. Drakar was launched with `NSWorkspace.openApplication` and quit with `osascript -e 'tell application id "io.mgcrea.Drakar" to quit'`. VS Code was launched as a direct exec of `Contents/MacOS/Code` and quit with `kill -TERM <pid>`, since its bundle id is shared with the owner's running VS Code.

Memory: the sum of `footprint -f bytes -p <pid>` ("Footprint:" line, the figure Activity Monitor shows) over the app's process tree, walked with `pgrep -P`, skipping any `claude` or `codex` child and its descendants. Sample after a minute: VS Code was still settling at 25 s.

A second, isolated VS Code needs all of these, each of which failed silently first:

- **A clean environment.** A shell running inside VS Code's extension host (any agent session started from the extension) inherits `ELECTRON_RUN_AS_NODE=1`, so `Code` starts as plain Node and exits. Launch it under `env -i HOME="$HOME" USER="$USER" TMPDIR="$TMPDIR" PATH=/usr/bin:/bin …`.
- **A short `--user-data-dir`.** VS Code's IPC socket (`<dir>/1.14-main.sock`) must fit in 103 characters, or it logs a warning with `--verbose` and quits. An agent's scratchpad path is too long; a symlink under `$TMPDIR` works.
- **A direct exec, not `open -n -a "Visual Studio Code" --args --user-data-dir …`.** On 2026-11-01 that never started a new instance (no log directory was written). Unexplained.
- **A helper extension to open the Claude tab.** A keystroke sent through System Events (⌘⇧Esc, `claude-vscode.editor.open`) did not land. What works is a two-file extension in the test `--extensions-dir`, registered in its `extensions.json`, with `"activationEvents": ["onStartupFinished"]` and `activate` running `vscode.commands.executeCommand("claude-vscode.editor.open")`. The window title then reads "Claude Code — <folder>", and a `claude` child appears.
- Install the extension into the test profile with `code --user-data-dir <dir> --extensions-dir <ext> --install-extension anthropic.claude-code`, and set `workbench.startupEditor: none` and `update.mode: none` in `<dir>/User/settings.json`.
